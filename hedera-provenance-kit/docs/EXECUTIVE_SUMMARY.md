# Hedera Provenance Kit — Executive Summary

**A reusable Scaffold-HBAR template for cryptographic provenance using SHA-256, Hedera Consensus Service, and Mirror Node verification.**

---

## The Problem

Digital applications increasingly need to prove that an artifact existed in a particular form without putting the artifact itself on-chain.

A document, dataset, research artifact, model artifact, software release, or other digital object may need independently verifiable provenance while its underlying contents remain private or stored elsewhere.

Developers shouldn't have to rebuild hashing, HCS submission, Mirror Node retrieval, verification, privacy boundaries, and transaction handling from scratch every time.

---

## The Solution

**Hedera Provenance Kit** packages that pattern into a reusable Scaffold-HBAR template.

The core workflow is:

```text
Artifact
   ↓
Canonicalization
   ↓
SHA-256
   ↓
Minimal Provenance Payload
   ↓
Hedera Consensus Service
   ↓
Hedera Consensus
   ↓
Mirror Node
   ↓
Cryptographic Verification
```

The artifact itself does not need to be placed on-chain.

Instead, the application anchors its cryptographic fingerprint and minimal provenance metadata through HCS.

Anyone with the appropriate provenance reference can independently retrieve the public record through a Hedera Mirror Node and verify that the recorded hash matches the expected artifact hash.

---

## Why HCS

Hedera Consensus Service provides the core provenance primitive used by the template.

The application uses HCS for:

* ordered provenance messages
* consensus timestamps
* durable public message history
* independently queryable records
* Mirror Node-based verification

HCS is therefore a functional part of the provenance architecture rather than an optional blockchain decoration.

---

## Privacy by Design

The template deliberately separates provenance from the underlying artifact.

### On-chain
* artifact identifier
* artifact type
* artifact version
* SHA-256 hash
* schema/version
* minimal provenance metadata

### Off-chain
* private documents
* PII
* patient information
* clinical records
* confidential research
* private source files
* credentials
* private keys

This allows developers to build verifiable provenance without putting sensitive application data on a public ledger.

---

## Developer Experience

The project is designed as a reusable Scaffold-HBAR template.

```bash
npm create scaffold-hbar@latest -- --template Zenieverse/hedera-provenance-kit
```

A developer can then configure a Hedera Testnet account and HCS topic, create a provenance record, submit it through HCS, and verify the resulting record through Mirror Node.

---

## Verification

Verification is not based solely on the existence of a transaction ID.

The template performs:

```text
HCS transaction
      ↓
Mirror Node retrieval
      ↓
Message decoding
      ↓
Schema validation
      ↓
Hash extraction
      ↓
SHA-256 comparison
      ↓
VERIFIED
```

A hash mismatch or malformed provenance message results in verification failure.

## Reference Implementation

The pattern was first proven inside the Dr. T platform's Hedera Commons integration.

The reusable Scaffold-HBAR template then extracted the core infrastructure pattern into a standalone developer-focused project.

The original Dr. T implementation and the reusable template are intentionally kept as separate repositories so the template remains framework-focused and independently scaffoldable.

## Security

The project is designed around secure credential handling.
